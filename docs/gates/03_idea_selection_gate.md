# Idea Selection Gate

**Deadline: T+60 minutes from challenge start**

The team must choose exactly one concept.

After approval, changing the core product idea is not allowed unless a fundamental blocker is discovered.

---

## Candidate Concept

### 1. Problem

What exact problem are we solving?

---

### 2. Target User

Who experiences this problem?

---

### 3. Existing Workflow

How is the task performed today?

---

### 4. Pain Point

What is slow, expensive, repetitive, confusing, risky or error-prone?

---

### 5. Proposed Solution

Describe the product in 1–2 sentences.

---

### 6. Why AI?

What specific step requires AI or benefits substantially from it?

What should remain deterministic?

---

### 7. End-to-End Demo Scenario

Write the exact critical path:

**Input → Processing → AI step → Action → Verification → User outcome**

---

### 8. Measurable Improvement

What can we show in the final pitch?

Examples:
- 10 minutes → 45 seconds;
- 6 manual steps → 2;
- 5 tools → 1 interface;
- unstructured input → verified structured action.

---

### 9. Main Technical Risk

What is most likely to break?

---

### 10. Fallback Plan

What is the smallest reliable version we can still demo if the ambitious version fails?

---

# Decision

- [ ] Concept accepted
- [ ] Concept rejected
- [ ] Fundamental uncertainty requires a short spike

## Acceptance Rule

Proceed only if all are true:

- [ ] Problem is clear in <30 seconds.
- [ ] User value is understandable.
- [ ] AI has a meaningful role.
- [ ] One end-to-end demo can be completed within the hackathon.
- [ ] Critical path can survive partial service/API failure.
- [ ] Team can explain what is real, mocked or synthetic.
