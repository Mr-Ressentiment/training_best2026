# BEST Minds 2026 — Mock Challenge Brief

## Challenge: AI That Gets Things Done

### Context

Generative AI systems are increasingly good at producing text, answering questions and summarizing information. However, many real-world processes still require people to manually:

- collect information from multiple sources;
- understand what matters;
- make repetitive decisions;
- transfer information between tools;
- verify whether something was actually completed;
- react when circumstances change.

A useful AI product should go beyond a chatbot.

Your challenge is to build an **AI-powered system that understands a real-world task and helps complete it from beginning to end**.

---

# The Challenge

## Build an AI-powered solution that transforms an inefficient human workflow into an intelligent, semi-automated process.

Your team may choose the domain and target users.

Possible domains include, but are not limited to:

- education;
- productivity;
- healthcare;
- accessibility;
- public services;
- transport;
- sustainability;
- small businesses;
- recruitment;
- cybersecurity;
- finance;
- logistics;
- event management;
- personal organization.

The problem must be specific enough that you can demonstrate measurable improvement over the current workflow.

---

# Core Goal

Your system should perform the following loop:

**UNDERSTAND → REASON → ACT → VERIFY**

## 1. Understand

The system receives information from one or more sources.

Examples:
- documents;
- messages;
- forms;
- datasets;
- APIs;
- images;
- user input;
- websites;
- schedules.

## 2. Reason

AI must perform a meaningful task rather than simply generate text.

Examples:
- classification;
- prioritization;
- extraction;
- comparison;
- anomaly detection;
- planning;
- recommendation;
- routing;
- summarization with evidence;
- decision support.

## 3. Act

The output should influence or trigger a useful workflow.

Examples:
- create a task;
- generate a structured report;
- prepare a response;
- update a record;
- create an action plan;
- route something to the correct person;
- call an API;
- schedule something;
- trigger an external service.

Human confirmation before an important action is allowed and encouraged.

## 4. Verify

The system should provide evidence that its result is trustworthy.

Examples:
- source citations;
- confidence information;
- validation rules;
- human approval;
- consistency checks;
- status tracking;
- before/after comparison.

---

# Minimum Product Requirements

## R1 — Real problem

Clearly identify:
- target user;
- existing workflow;
- pain point;
- why existing solutions are insufficient.

The problem should be understandable in less than 30 seconds.

## R2 — Working end-to-end prototype

Judges must be able to see the complete critical path:

**input → AI processing → useful output/action**

A collection of disconnected screens or a static UI mockup is not sufficient.

## R3 — Meaningful AI component

AI must be necessary to the solution.

Simply adding a chatbot interface to a conventional application will not be considered strong use of AI.

The team should be able to explain:
- what AI does;
- what deterministic software does;
- why AI is useful at that specific point.

## R4 — Grounded outputs

When the system uses external information, the user should be able to understand where important conclusions came from.

Acceptable mechanisms include:
- citations;
- source links;
- highlighted evidence;
- structured provenance;
- retrieved context.

## R5 — Failure handling

Demonstrate at least one case where:
- data is missing;
- AI is uncertain;
- an external service fails;
- user input is ambiguous;
- the requested action cannot safely be performed.

The system should degrade gracefully rather than silently inventing an answer.

## R6 — Human control

Actions with meaningful consequences should either:
- require human confirmation;
or
- provide a clear mechanism for review or reversal.

# Bonus Features

Optional:
- multi-agent workflow where specialization is justified;
- multimodal input;
- external integrations;
- proactive behavior;
- explicit evaluation layer.

---

# Constraints

Teams may use:
- open-source software;
- public APIs;
- commercial AI APIs;
- locally hosted models;
- existing frameworks and libraries.

Existing general-purpose infrastructure may be reused.

The submitted product-specific solution should primarily be created during the hackathon.

AI-assisted development is allowed.

Teams remain responsible for:
- understanding their system;
- explaining architecture;
- verifying generated code;
- respecting licenses;
- demonstrating that the final application works.

Sensitive personal data should not be required for the demo.

Synthetic data must be clearly identified as synthetic.

---

# Expected Deliverables

By the end of the hackathon, each team should provide:

1. Working prototype.
2. Source-code repository.
3. README with setup instructions.
4. Short architecture description.
5. 3–5 minute final pitch.
6. Live or recorded demonstration of the critical workflow.

---

# Final Challenge Statement

> **Build an AI system that turns information into trustworthy action.**

Choose a real problem, create a working end-to-end solution and demonstrate that AI provides measurable value beyond a conventional chatbot.
